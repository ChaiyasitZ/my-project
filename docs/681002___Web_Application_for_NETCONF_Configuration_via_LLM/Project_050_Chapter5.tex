\chapterTitle{5}{สรุปผลการดำเนินงาน}

\section{สรุปผลการดำเนินงาน}
\hspace*{1.3em}
โครงการ เว็บแอปพลิเคชันเพื่อการคอนฟิกด้วยวิธี NETCONF ผ่าน LLM ได้พัฒนาระบบอัตโนมัติสำหรับการจัดการและสร้างการคอนฟิกอุปกรณ์เครือข่ายโดยใช้เทคโนโลยี Large Language Model (LLM) ผ่าน Ollama ที่รันบนเครื่องผู้ใช้
ระบบนี้ประกอบด้วยส่วน Frontend ที่ใช้ React 19 และ Vite 6, Backend ที่ใช้ Node.js และ Express ที่ Deploy บน Vercel Serverless พร้อมฐานข้อมูล MongoDB Atlas และ Desktop Agent (Electron Application) สำหรับเชื่อมต่อกับอุปกรณ์เครือข่ายและ Ollama LLM ผ่านระบบ Agent Relay แบบ HTTP Polling
ผลลัพธ์ที่สำคัญของโครงการคือการสร้างระบบที่สมบูรณ์ ซึ่งครอบคลุมการจัดการอุปกรณ์เครือข่าย การสร้างคำสั่งคอนฟิกด้วย LLM (รองรับการสร้างคอนฟิกให้หลายอุปกรณ์พร้อมกันในโหมด CLI) การสำรองข้อมูลด้วย Interactive Shell พร้อมทำความสะอาดผลลัพธ์อัตโนมัติ การ Restore คอนฟิกพร้อม Checkpoint อัตโนมัติ การเชื่อมต่อผ่าน Agent Relay (Long-polling สูงสุด 55 วินาที พร้อม Extended Polling สำหรับ Restore) ไปยัง Desktop Agent สำหรับ SSH, NETCONF (พร้อม Auto-Connect), YANG Model Management และ Console Port Scan ผ่าน Agent Relay พร้อมแสดง Port ทุกประเภท
ทำให้ผู้ดูแลระบบเครือข่ายสามารถจัดการอุปกรณ์ได้อย่างมีประสิทธิภาพ ลดเวลาในการสร้างการคอนฟิกแบบดั้งเดิม และลดข้อผิดพลาดที่อาจเกิดขึ้นจาก Human Error
ส่งผลให้ผู้ดูแลระบบสามารถมุ่งเน้นไปที่การวางแผนและพัฒนาโครงสร้างเครือข่ายได้อย่างเต็มที่
\section{ปัญหาและอุปสรรค}
\begin{mycustomenum}[label=5.2.\arabic*] 
    \item การจัดการ SSH Connections ผ่าน Agent Relay เนื่องจาก Backend อยู่บน Vercel Serverless ไม่สามารถเชื่อมต่อ SSH โดยตรงได้ จึงต้องพัฒนาระบบ Agent Relay ที่ใช้ HTTP Polling ผ่าน MongoDB command queue เพื่อส่งคำสั่งไปยัง Desktop Agent ที่รันบนเครื่องผู้ใช้
    \item การจัดการ Configuration ในการสร้างการคำสั่งคอนฟิกที่ถูกต้องและเหมาะสมกับอุปกรณ์แต่ละประเภท (router, switch, nexus, ios-xe) เป็นเรื่องที่ต้องอาศัยความรู้เฉพาะทางและการทดสอบอย่างละเอียด
    \item การแก้ไขข้อผิดพลาดของ LLM ที่รันบน Ollama สร้างคำสั่งคอนฟิกที่ไม่ถูกต้อง การวิเคราะห์และแก้ไขข้อผิดพลาดเหล่านั้นอาจเป็นเรื่องที่ท้าทาย
    \item ปัญหา NETCONF Connection Stateless บน Vercel Serverless ที่ทำให้ NETCONF sessions หายไปเมื่อ Serverless Function instance เปลี่ยน ส่งผลให้การดำเนินการ NETCONF ล้มเหลวด้วยข้อผิดพลาด ``Not connected via NETCONF''
    \item ปัญหาการสำรองคอนฟิกด้วย SSH Single Exec ที่ส่งหลายคำสั่งพร้อมกัน (\texttt{terminal length 0\textbackslash nshow running-config}) ซึ่งอุปกรณ์ Cisco ไม่รองรับ ทำให้ได้ข้อความผิดพลาดแทนคอนฟิกจริง
    \item ปัญหา Agent Relay Timeout (เดิม 25 วินาที) ไม่เพียงพอสำหรับการ Restore คอนฟิกที่ต้องสร้าง Checkpoint + Deploy คอนฟิก ส่งผลให้ Restore ล้มเหลวด้วยข้อผิดพลาด 500
    \item ปัญหา YANG Model Upload ล้มเหลวเนื่องจาก Auth Middleware ใช้ \texttt{.lean()} ที่ทำให้ \texttt{req.user.id} เป็น undefined (ไม่มี Mongoose Virtual Getter) และ HTML5 Validation ปิดกั้นค่า Namespace ที่ไม่ใช่ URL
    \item ปัญหา Console Port Scan ไม่แสดง Port ใด ๆ บน Vercel Serverless เนื่องจาก \texttt{consoleService.getAvailablePorts()} จัดการ Error ภายในตัวเอง (ส่งคืน \texttt{\{ success: false, ports: [] \}} แทนที่จะ throw) ทำให้ Route ไม่ Fallback ไปยัง Agent Relay เมื่อ SerialPort (Native Module) ไม่พร้อมใช้งานบน Serverless
\end{mycustomenum}

\section{การแก้ปัญหา}
\begin{mycustomenum}[label=5.3.\arabic*] 
    \item พัฒนาระบบ Agent Relay สร้างระบบ HTTP Polling แบบ command queue ผ่าน MongoDB โดย Desktop Agent ดึงคำสั่งทุก 2 วินาที และส่ง heartbeat ทุก 5 วินาที พร้อม long-polling สำหรับคำสั่งที่ต้องการผลลัพธ์เร็ว (maxWait สูงสุด 55 วินาที ภายในขีดจำกัด Vercel 60 วินาที)
    \item สร้าง Configuration Validation สำหรับการสร้างคำสั่งคอนฟิกเพื่อให้ผู้ใช้สามารถใช้งานได้ทันที
    \item ระบบ Backup และ Rollback พัฒนาระบบสำรองข้อมูลด้วย Interactive Shell ที่ส่งคำสั่งแยกกันตามลำดับ พร้อมทำความสะอาดผลลัพธ์อัตโนมัติ (ลบ ANSI codes, Command Echo, Device Prompt) และการ rollback พร้อม Checkpoint อัตโนมัติเพื่อลดความเสี่ยงจากการคอนฟิกที่ผิดพลาด
    \item พัฒนาระบบ NETCONF Auto-Connect โดยเพิ่มฟังก์ชัน ensureConnected() ใน Desktop Agent ที่ตรวจสอบและเชื่อมต่อ NETCONF อัตโนมัติก่อนดำเนินการทุกครั้ง พร้อมส่ง Device Credentials จาก Backend เพื่อรองรับ Vercel Serverless ที่ไม่มี persistent state
    \item แก้ไข Agent Relay Timeout โดยเพิ่ม maxWait จาก 25 เป็น 55 วินาที เพิ่ม Deploy timeout เป็น 45 วินาที และเพิ่มระบบ Extended Polling สำหรับ Restore ที่รอผลลัพธ์เพิ่มเติมหลัง Relay timeout
    \item แก้ไข YANG Model Upload โดยเปลี่ยน req.user.id เป็น req.userId ในทุก Route (8 จุด) และแก้ไข HTML5 Validation บน Frontend
    \item แก้ไข Console Port Scan โดยเพิ่ม \texttt{serialPortAvailable} flag ใน ConsoleService Constructor ที่ตรวจสอบว่า SerialPort (Native Module) พร้อมใช้งานหรือไม่ แล้วแก้ไข Console Routes ทั้ง 6 เส้นทาง (ports, connect, disconnect, test, command, initial-config) ให้ตรวจสอบ flag นี้ก่อน --- หาก false จะข้ามไปใช้ Agent Relay โดยตรง นอกจากนี้ยังลบ Port Filtering ออก (เดิมกรอง Bluetooth/Virtual/Loopback ออก) เพื่อให้แสดง Port ทุกประเภทรวมถึง USB-to-Serial Adapter
\end{mycustomenum}

\section{ข้อเสนอแนะ}
\begin{mycustomenum}[label=5.4.\arabic*] 
    \item พัฒนาฟีเจอร์เพิ่มเติม เช่น การสร้าง network monitoring dashboard, การวิเคราะห์ performance metrics, หรือการเพิ่มความสามารถในการรองรับอุปกรณ์จากผู้ผลิตอื่นๆ ให้หลากหลายมากขึ้น
    \item พัฒนา API Integration เพื่อให้สามารถเชื่อมต่อกับระบบ network management อื่นๆ และสร้าง ecosystem ที่ครอบคลุมการจัดการเครือข่ายแบบองค์รวม
    \item เพิ่มระบบ Persistent NETCONF Session Management ด้วย Redis หรือ Database เพื่อลดการ Auto-Connect ซ้ำบ่อยครั้งบน Vercel Serverless
    \item พัฒนาระบบ Scheduled Backup อัตโนมัติที่ Desktop Agent ดำเนินการตามตารางเวลาที่กำหนดโดยไม่ต้องรอคำสั่งจาก Backend
\end{mycustomenum}
